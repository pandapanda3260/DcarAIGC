# 小红书汽车内容三命题评估：执行说明

## 1. 先区分三个问题

- **内容是不是汽车类**：优先判断笔记标题、正文、话题、图片 OCR、视频字幕/语音。评论不是必要输入。
- **互动受众是不是偏汽车**：评论只能观察主动评论者的讨论倾向，不能代表全部曝光用户，更不能直接证明整篇笔记的全部流量都是汽车垂类。
- **是否具备懂车帝用户拉新潜力**：综合内容属性、互动用户倾向、懂车帝功能承接和用户下一步行动意图得出预测分；它不是下载概率或实际新增效果。

每篇最终可评分样本只输出三个独立结果：

1. `content_auto_score`：内容汽车属性，0–100分。
2. `audience_auto_score`：互动用户汽车倾向，0–100分。
3. `dcd_acquisition_score`：懂车帝用户拉新潜力，0–100预测分。

命题2、3要求至少20名有效独立评论用户。评论取不到、已确认0评论或有效用户不足时显示`—`及数据状态，不得用0分或50分代填。

非汽车笔记是重要对照组：如果非汽车内容下仍持续出现汽车讨论，才更像账号受众产生的跨内容延续；如果汽车讨论只出现在汽车内容下，更可能只是被内容本身触发。

## 6. 最小验证实验

同一批标注样本比较三个版本：

1. 只看内容。
2. 只看评论。
3. 内容与评论联合。

分别计算准确率、召回率、精确率和“证据不足”比例。若目标是判断内容类别，以“只看内容”为基线；若目标是研究受众倾向，则比较汽车笔记与非汽车笔记中的汽车相关评论率，并明确结论仅适用于评论区互动受众。

```bash
  --report pilot_three_proposition_report_v1.md \
  --summary pilot_three_proposition_summary_v1.json \

```

生成器会先校验数据合同：评论未达标时命题2、3必须为`null`；评论达标时人数分桶、命题2分数和命题3公式必须一致；尚未开展懂车帝侧实验时，实际新增字段也必须为`null`。校验失败会停止生成，防止把数据缺失写成业务结论。

`/Users/mark/Documents/DcarAIGC/src/dcar_eval/xhs_browser_comment_collector.js`
