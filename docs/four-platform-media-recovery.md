# 四平台媒体与来源更新实现

本次只实现流程和离线验证，不启动历史补齐、归档激活、正式数据库迁移或付费采集。

## 本地媒体主链

`pipeline.run_local_content_analysis` 保留已启用的账号资格与近 30 天范围，视频类型覆盖抖音、小红书、快手、视频号。图文目前仅抖音、小红书通过现有合同；快手、视频号未知媒体类型保留为 `unknown`，可保存合法的作品和指标事实，在待办里显示类型未核验，不能冒充分析成功。

本地昂贵计算并发仍为 1。锁按一条作品获取，繁忙时非阻塞退出并保留 `local_processing_busy` 待办，不增加内容失败次数。待下载来源按平台轮转，最多连续 4 条下载优先项后安排一条最早等待项；下一轮从最近持久化处理的平台之后继续。存在明确来源过期时间时优先使用该时间，未声明的来源不虚构 TTL。

来源失效后先复用已获得的最新、可校验详情 raw，校验作品、作者、媒体类型和原始响应摘要；较新的失败或未知结果会挡住较老成功记录。此路径不调用供应商，不绕过原下载次数上限，不免费重新获取到期原件。

## 视频号解密

依据 TikHub 官方详情文档 `https://docs.tikhub.io/472974842e0` 所链接的公开实现，固定采用 WxIsaac64 1.2.46。源代码、MIT 许可、固定提交和文件 SHA-256 见 `src/dcar_eval/v8/vendor/wechat_video_decode/README.md`。

仅接受已验证类型 `media_type=4`，兼容同一合同的 `object_desc` / `objectDesc` 字段。URL、token、decode key 必须来自同一份经过摘要校验的 raw、同一个媒体对象。Node 只使用随源码冻结的 JS/WASM，stdin 接收精确十进制 key，不使用运行时下载和网络。

下载进入有字节上限的私有临时文件，仅解密前 128 KiB；通过 MP4 结构、视频流、帧和整段 ffmpeg 音视频解码后才发布明文媒体。加密摘要、明文摘要、raw 编号和 raw 摘要保存在媒体处理回执，key 和密钥流不进入公开 API 或媒体元数据。缓存复用和陈旧槽恢复继续验证该回执。

官方公开完整样本 14,088,528 字节已实际通过整段解码，时长 52.314671 秒；摘要记录在 vendor README，视频不随应用分发。运行环境缺少 Node 或固定资源损坏时返回 `decryption_runtime_unavailable`，不得显示解密成功。

## 待办及付费边界

内容页的“待处理媒体与链接”视图及相关跳转入口已于 2026-09-13 删除，内容页直接显示筛选和内容列表。以下为保留的后台接口合同。`GET /api/v8/media/pending-work` 只读投影当前媒体状态，可按平台、账号、阶段和原因筛选。每项包括首次等待、最近失败、来源 raw、来源采集时间和下一步处理方式。打开、筛选和轮询不会派发任务。

免费重试和原件恢复沿用已有受限接口。来源付费更新使用两阶段合同：

1. `POST /api/v8/contents/{id}/media/source-refresh/prepare`，提交 `request_id` 和 `source_generation`，冻结作品、来源代际、1 次详情请求及对应美元价签，返回 proposal，不派发。
2. 用户查看费用后调用同路径 `/execute`，提交 `task_id` 和 `source_generation`，原子登记现有 `capture_manual_command`。现有捕获 worker、费用账本、发送资格、raw 保存与结果不确定状态继续生效。

独立 `logical_due` 绑定 proposal 和源代际，不借用旧 lifetime 槽或正在执行的旧任务。同来源的两标签页不能登记两份执行；任何一次物理发送都用完本次 1 请求额度，包括未计费或结果不确定的发送。过期但从未发送的任务只有在运营再次点击准备时才可重新报价；已经发送的任务不能靠换 request id 重买。成功 raw 的本地回放不受报价 TTL 阻挡。

报价有效期固定为 1 小时。轮询只读展示到期且无发送、raw 或活动 work/slot 的任务，提示重新查看费用并确认，不延长授权或自动购买。显式准备动作仍重复校验这些条件；存在结果不确定的发送时保留阻断状态。调度器在原 4 并发、每轮 16 项中最多安排 2 个来源更新优先位置，其他位置继续照顾四平台普通采集和账号准备；到期未发送项也经原授权校验零付费结束，成功 raw 仍可在该通道继续本地保存。

尚可查阅或免费恢复的归档原件不开放付费再获取。到期原件仅允许本次已确认任务的成功详情 raw 所产出的新来源创建新 bundle、新下载槽；旧实例、归档记录和到期时间保持不变。归档激活状态不会随本次修复自动改变。

来源更新任务继续保存在 proposal 和 `read_command` 中，不依赖工作台 sidecar 的内容更新记录。未解析分享链接继续由后台独立保存；未返回真实内容 ID 前不提示已入库。上述状态不再通过独立待办视图展示。

## 评论合同

视频号评论通过共享 `comment_paging`，完整保留 opaque cursor 与回复上下文，分别生成内容范围和平台范围 HMAC 后进入业务表。重复回放不重复请求；只将一级评论计入受众分母。快手评论仍明确能力未验证，不根据空接口示例猜测字段。

## 离线验收入口

- `tests/test_v8_wechat_video_crypto.py`：固定算法向量、精确大整数、同源 URL/token/key、错误密文不发布、整段验证、raw 与缓存/恢复绑定。
- `tests/test_v8_media_work_queue.py`：四平台能力、轮转与最早等待、防止 GET 写入或加入历史任务。
- `tests/test_v23_media_source_refresh.py`：两阶段 API、一次请求额度、双标签页幂等、代际变化、过期报价、成功 raw 回放、旧到期实例保留和新实例登记。
- `tests/test_v8_new_platform_capture_integration.py` 的视频号共享评论分页回放测试：两页游标、用户 HMAC、保存及零费用重放。

发布验收必须另行确认：冻结源码包含指定 vendor 字节，运行 Writer PATH 能找到 Node，已安装构建匹配父版本与 schema23 迁移证明。离线样本通过不等于已经切换正式 Writer 或完成实际平台采集。
