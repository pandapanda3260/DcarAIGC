## 结论

已确认：使用当前已登录的小红书 Chrome 会话，可以取得公开 HTML 中缺失的动态评论正文，并能通过评论区滚动触发下一批加载。

此前的 `collect_xhs_public.py` 使用独立 `curl`，没有读取 Chrome 登录态。它成功取得正文和媒体，但 P001 的嵌入评论数为 0。因此之前只能说明“公开首屏 HTML 未提供评论正文”，不能说明 Chrome 未登录是所有失败路径的原因。

万邦的 `4010/api_init` 与 Bright Data 的 `robots.txt` 限制仍与本机 Chrome 登录无关。

## 可复用入口

`xhs_browser_comment_collector.js` 是登录态页面内的 DOM 采集适配层。它会滚动 `.note-scroller`、累计评论、去除身份字段，并在达到目标独立用户数或滚动稳定后停止。

它不能由当前 Python `curl` 脚本直接继承登录态；使用时应在已登录 Chrome 的笔记页面中作为 DevTools Snippet 运行：

```js
await xhsBrowserCommentCollector.collect({ targetUniqueUsers: 30 })
```

默认不写文件、不发评论、不修改账号，只返回去标识化结果。批量化前仍应先补一篇视频笔记验收，并保持低频采集。
