# 万邦小红书评论接口故障诊断

诊断日期：2026-07-19

## 结论

无法取到评论的直接原因不是笔记没有评论，也不是本地 Key 文件、笔记 ID、`cursor` 或解析器先出错。万邦在执行评论业务之前就返回：

```text
HTTP 200
error_code = 4010
reason = 不存在相应的数据信息api_init
```

万邦官方错误码定义中，`4010` 是“API不存在”，`4012` 才是“请先添加API”。因此这是 `smallredbook.item_review` 的供应商路由/产品状态问题，不能通过反复换笔记或本地重试修好。

截至 2026-07-19 的最新复核进一步表明：万邦当前公开产品目录已经不再列出小红书，旧 `smallredbook` 文档地址和三个已知网关端点也全部返回 `4010/api_init`。在万邦提供新的准确命名空间和 `error_code=0000` 成功样例之前，应把万邦小红书能力视为当前不可用，而不是“账号尚未开通”。

## 最新官方目录与端点复核（2026-07-19）

1. 万邦《电商平台 API 所有功能列表》标注更新时间为 2026-06-26；平台支持列表和“更多平台”中均未列出“小红书”或 `smallredbook`。
2. 当前官方 API 文档页面的平台选择器中没有小红书入口。
3. 直接访问下列旧文档地址，页面均返回 `error_code=4010`、`reason=不存在相应的数据信息api_init`：
   - `smallredbook.readme.html`
   - `smallredbook.item_review.html`
   - `smallredbook.item_get_video.html`
   - `smallredbook.item_get_video_pro.html`
4. 使用本地 Key 各做 1 次受控请求，三个已知端点均返回 `4010`：
   - `smallredbook.item_review`
   - `smallredbook.item_get_video`
   - `smallredbook.item_get_video_pro`
5. 官方错误码表明确区分：`4010 = API不存在`，`4012 = 请先添加API`。当前收到的是前者，因此不能通过充值、重复添加 API 或更换笔记 ID 解决。

官方参考：

- https://open.onebound.cn/help/api/
- https://open.onebound.cn/help/api/smallredbook.item_review.html
- https://www.onebound.cn/daigou/api-list.pdf

## 实测证据

1. 本地请求地址与官方文档一致：`https://api-gw.onebound.cn/smallredbook/item_review/`。
2. 必需参数与官方文档一致：`key` / `secret` / `num_iid`；首页不需要 `cursor`。
3. 使用万邦官方公开测试 Key 和官方文档的示例笔记，仍返回同一个 `4010/api_init`。这排除了用户 Key 独有配置和本次笔记 ID 异常。
4. 使用本地 Key 做了 1 次新版诊断请求，状态已正确记为 `provider_api_unavailable`，见 `onebound_smoke_v2_results.csv`。官方文档标注 `4010` 不收费。
5. 公开小红书页面上多篇笔记显示有评论数，但首屏 SSR 的评论正文为空；这不能被记为真实 0 评论。

官方参考：

- https://open.onebound.cn/help/api/smallredbook.item_review.html
- https://www.onebound.cn/daigou/api-list.pdf

## 本地已修复的问题

`fetch_onebound_comments.py` 现在会：

- 将 `4010` 标记为 `provider_api_unavailable`，不再误写成“0条评论”。
- 首页不传空 `cursor`，后续页才携带游标。
- 兼容 `items.item` / `items.list` / `data.comments` 等常见响应包络。
- 兼容多种子评论与分页字段。
- 区分 API 节点数、解析评论数、外部独立用户数和有效独立用户数。
- 使用不可逆 HMAC 摘要按用户去重，不保存原始用户 ID 和昵称。
- 排除作者回复、纯表情/标点、引流广告与无法去重的评论。
- 将结果分为供应商不可用、解析失败、确认0评论、不足20人和可评分等状态。

本地修复已通过自动化夹具测试，但不能替万邦恢复服务端路由。

## 可直接发给万邦客服

```text
2026-07-19 调用 https://api-gw.onebound.cn/smallredbook/item_review/，
HTTP 200，error_code=4010，reason=不存在相应的数据信息api_init。
使用官方公开测试 Key 和官方示例笔记也得到同一结果。
请确认 smallredbook namespace 及 smallredbook.item_review 当前是否在线，
以及当前是否已经更换 API namespace 或 API name。请先提供一次 error_code=0000 的成功样例，
包含 api_type=smallredbook、非空 items.item 以及可正常翻页的 cursor/has_more。
笔记详情还需同时提供一个可用接口名称及包含标题、正文、图片或视频字段的成功返回。
```

只向客服提供 Key 末 4 位，不要发送 secret。在万邦给出 `0000` 成功样例前，不建议继续购买或重复调用这一接口。

## 恢复验收标准

万邦恢复后，先只测 1 篇页面已显示有大量评论的笔记，必须同时满足：

1. `error_code=0000`。
2. API 原始评论节点数 > 0。
3. 解析评论数 > 0。
4. 有效独立外部评论用户 >= 20。
5. `cursor/has_more` 无重复、无停滞。

五项全部通过后，才执行 10 篇抽检和补抽。
