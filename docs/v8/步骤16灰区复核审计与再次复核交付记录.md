## 再次复核的 append-only 规则

1. 再次复核只允许针对已 `resolved` 的队列发起，必须记录发起人、发起原因、原复核记录和发起时的当前评估版本。
2. 发起再次复核不删除、覆盖或改写旧的 `evaluation_reviews`、`manual_evidence`、`evaluation_versions` 或原队列审计信息。
3. 提交新判定时，必须以发起时的当前评估 ID 作为 `base_evaluation_id` 执行乐观锁检查；基准过期时返回 409，刷新证据后重新判定，不得静默覆盖。
4. 新提交必须追加一条新 `evaluation_reviews`、一份新 `manual_evidence` 和一个 `evaluation_source=manual_review` 的新评估版本；旧版本仍可审计。
5. “认可并保留”不生成冗余版本；只有业务人员不认可当前 Codex 判定时，才在证据工作台发起并完成再次复核。
6. `2Z4EHR` 存在 `C1 + new_car` 与已发布词表场景不一致，必须再次复核；在新判定提交前不得将其标记为业务确认。
