## 1. 机制说明（新增能力，提交前先读）

本次代码变更（回归门槛见第 2 节）：

- `v8/range_backfill.py`：新增 `--full-history`（区间起点固定 2010-01-01）、`--archive-before`（入库时自动分组标记）、`--history-only`（content/status 只覆盖 `history-*` 标记内容，防止重买既有语料）、`--workers 1-8`（discover/content/fetch-repaired-metrics 有界并发）、`--compact`（十万级输出/状态压缩为汇总+失败明细）、`tag` 与 `status` 两个新阶段、长跑每 200 条刷新状态文件、按条异常隔离（单条炸不掉整晚）。
- `scripts/run_full_history_backfill.py`：一键自动驾驶（见 0.5 节）。
- `v8/storage.py`：新增 `history-archive` / `history-backfill` 两个 source_group 常量。
- `v8/evaluation.py`：`incremental_candidates` 排除上述两类标记内容（防止历史入库当晚被增量评估灌成纯文本灰区洪水）。
- `v8/scheduler.py`：`run_media_cutoff` 排除上述两类标记内容（防止入库当日 07:30 把几万条历史内容塞进 `media_processing_incomplete` 人工复核并卡住正式报告闸门）。
- 新增测试 `tests/test_v8_history_backfill_scopes.py`（9 条）。

标记语义（`content_items.source_group`，只会打在"从未产生过评估版本且分组为空"的行上，既有语料零影响）：

- `history-archive`：published < archive-before。仅入库+指标+评论，**永不**自动评估、不做媒体。这是决策口径，不是缺陷。
- `history-backfill`：archive-before ≤ published ≤ end 的回溯入库内容。等 `local-evidence --tagged-only` 完成媒体+评估后**当场清标**，回归常规增量链路。清标前不进增量评估、不进当日媒体截止闸门；30 天监控窗内的每日指标/评论刷新**不受**标记影响。

断点与预算：所有阶段基于幂等槽（同窗成功槽重放不计费）。每阶段用独立 task_id；task 预算合同（task_id + --max-amount）建立后不可改——**预算触顶想追加时，换一个新 task_id 重跑同一命令**，已成功部分自动免费重放，只有未完成部分继续计费。

## 8. 阶段 5：证据窗媒体+评估（本地免费，分晚推进）

磁盘先算账：`history-backfill` 剩余条数 × ≈4.4MB（现有均值）。当前盘剩 ~614GB，近 6 个月量级预计数十 GB，可行；若 status 显示证据窗条数异常大，先缩小窗口（把 local-evidence 的 `--start` 收紧到 3 个月）再议。

```bash

$RB local-evidence --full-history --end "$FH_END" \
  --task-id fh-local-01 --max-amount 1 --limit 800 --tagged-only --compact
```

推进与收尾：

```sql
-- 剩余待办（目标：归零）
SELECT platform, COUNT(*) FROM content_items WHERE source_group='history-backfill' GROUP BY 1;
-- 反复失败的卡住项（通常是媒体源过期/已删除）
SELECT c.id, c.link_id, c.canonical_url FROM content_items c
WHERE c.source_group='history-backfill' ORDER BY c.published_at DESC LIMIT 50;
```

卡住项处置：媒体源过期用 `retry_content_media(content_id, allow_paid_refresh=True)` 花 $0.001/$0.01 刷新后重跑本阶段；确认媒体不可恢复（原视频已删）就接受文本级证据：手工清标 `UPDATE content_items SET source_group='' WHERE id=<id>;`，当晚增量评估会以现有证据评估并按正常灰区流程处理。**尽早跑第一批**——发现页里的媒体直链有时效，拖得越久过期越多。

`history-archive` 组永久保留标记（决策口径）。若日后想给某段历史补媒体+评估：把该段标记改成 `history-backfill` 再走本阶段即可，其余机制自动衔接。
