# 步骤 11：媒体证据自动链路修复记录

## 本步修改

- 详情响应写入后提取供应商视频或图片原始地址，保存为带 SHA-256 的 `media_source` 证据登记；封面、头像、音乐和分享图不进入媒体源。
- `更新数据` 默认在详情抓取后立即执行本地媒体下载与证据处理；自动采集使用分段模式，避免 02:00 的供应商抓取被本地计算阻塞。
- 调度器固定为六个任务：02:00 采集、02:20 媒体下载与每日最多 20 条历史补证、03:00 ASR/OCR、07:30 媒体截止与增量评估、08:00 日报、周一 08:30 周报。
- 视频自动生成下载文件、关键帧、ASR 和 OCR；图文自动生成图片清单和 OCR。所有处理继续使用唯一处理槽，成功结果不重复计算。
- 07:30 只统计当天新入库或当天完成详情抓取的内容；不完整内容进入 `media_processing_incomplete` 人工队列，完整内容解除该原因并进入增量评估。
- 历史补证只有预算状态为 `approved` 时才按每日配额放量；`draft/pilot` 只走小样本，`suspended` 不发起供应商请求。
- 自动处理队列必须存在 v8 `media_source`，不会把迁移时登记的 750 条历史媒体资产重新计算。
- 旧缓存二进制 `data/cache/douyin_media/bin/vision_ocr` 已移入废纸篓；`runtime/bin/vision_ocr` 是唯一运行版本。
