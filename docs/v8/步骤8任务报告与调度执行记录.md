# 步骤 8：任务、报告与调度

## 修改内容

- 新增日报、周报和自定义报告任务；自定义任务只接受自然日闭区间。
- 任务首次执行冻结内容边界，缺失 `published_at` 的内容明确登记为
  `excluded_missing_boundary`。后续重试只追加 revision，不修改旧 revision。
- 新增 v8 JSON、Markdown、内容 CSV、SVG 和 PNG 报告产物。PNG 使用 macOS
  `qlmanage`，不可用或失败时下载路由确定性回退 SVG。
- 新增任务详情、重试、报告读取和 per-run 文件下载 API；任务页接入新建任务、
  五个详情页签、revision 文件和事件日志。
- v8 合同不再硬编码卖点 v5.0，而是校验正式版本格式并在每个 revision 中冻结
  实际已发布词表版本。评估规则和证据合同仍严格固定。
- 内嵌 APScheduler 固定四个时刻：每天 02:00 准备并执行到期抓取、每天 02:30
  增量评估、每天 08:00 生成昨日日报、周一 08:30 生成上一自然周周报。
  启动时补跑最近遗漏槽，每日最多回看 7 天、每周最多回看 28 天；同一
  `(job_id, scheduled_for)` 幂等。
- `sample_only` 只允许用于有明确抽样设计、且结论明确限定为样本的指标；普通抓取
  覆盖不足统一使用 `below_threshold`，两者不得互换。

## 本步骤发现并修复的问题

- 已发布卖点标准升级到 v5.1 后会被旧 v8 合同错误拒绝；已改为冻结并验证实际
  正式词表版本，新增正反测试。
- 任务实际生成后，步骤 5 的“列表永远为空”断言失效；已按新业务预期重写为
  列表合同断言，同时保留临时库中对创建、revision 和下载的严格端到端断言。

  登记，`summary-image` 下载优先 PNG、失败回退 SVG。
