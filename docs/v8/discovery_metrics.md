# 抓链接时处理内容指标

系统的作品列表采集统一使用 `providers.materialize_account_discovery_page` 入库。
该入口先关联内容、保存列表响应中的指标，再把本页缺失或过期的指标交给
`capture_runtime.enqueue_discovered_metrics`。不再另写只保存链接 JSON 的业务流程。

## 执行顺序

1. 保存完整接口原始响应，校验账号、内容身份和发布时间范围。
2. 链接入库时保存接口附带指标，保留原始接口、响应 ID 和实际采集时间。
   已有内容以及跳过详情、复用媒体的内容也执行此步。同一原始响应重放不重复登记。
3. 对本页属于当前采集范围的内容，按正式字段来源规则检查缺项、过期项，
   立即创建持久化补抓任务。已有周期、预算和请求去重规则继续生效。
   此步只安排任务，供应商请求由正常采集队列执行。
4. 下载与内容分析单独进行。媒体不可下载、没有评估结果，不是指标任务的前置条件。
5. 交付时读取正式字段值、来源、采集时间及缺失原因。请求结束或下载完成不等于指标齐全。

## 抖音指标来源

| 字段 | 补抓接口 |
| --- | --- |
| VV、点赞数 | 视频统计 |
| 评论数、分享数、收藏数 | 视频详情；作品列表已返回的有效值直接复用 |

schema 20/21 的补抓缺项判断与正式 v3 字段来源规则一致。列表附带的 VV、点赞可保留供溯源，
但不能据此跳过所需的统计接口。有效数值可以增加也可以减少；占位零、缺失或失败不会
覆盖已有有效值或更新其成功采集时间。

## 重放与失败

本地入库或排队失败时，复用已保存响应重放；不会为修复本地失败重新购买同一页。
重复链接、重复页和定时规划使用同一内容、接口和周期标识去重。
接口失败、收费未知、尚待处理和字段缺失分别保留，不能写成零或报为已补齐。
未启用集成采集的旧运行模式仍由其原调度处理，原始指标保存不依赖该调度开关。

本变更固定今后的系统流程，不启动历史全量重抓，也不修改历史指标的采集时间。
