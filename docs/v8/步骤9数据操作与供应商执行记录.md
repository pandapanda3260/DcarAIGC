# 步骤 9：数据操作与供应商执行记录

## 修改内容

- 账号以规范化手机号为唯一键，支持新增、修改、POST body 搜索、多维筛选、CSV 导入和完整手机号导出。
- CSV 账号导入兼容导出文件的平铺平台字段；同文件重复手机号由最后一行覆盖。账号身份未变化时保留供应商引用，避免重复购买 UID 转换。
- 内容以平台内容 ID 为主身份；抖音和小红书解析失败拒收，视频号和快手允许规范化链接兜底。支持新增、修改、搜索、筛选、校验后批量导入、导出和逐条更新。
- 内容搜索返回最近阅读/播放、评论快照和重复来源链接 ID；业务预估三项在没有模型前继续显示“暂不可计算”。
- 抓取新增账号级发现链路：抖音数字 UID 只转换一次并缓存 `sec_user_id`，随后拉最新作品；小红书按用户 ID 拉已发布笔记。新发现内容先身份 upsert，再进入详情、指标和评论链路。
- 抓取成本按业务窗口全局去重，不再只按供应商/适配器去重：详情终身最多成功一次、指标每日最多成功一次、评论每周最多成功一次；失败允许原槽重试。
- 调度器 02:00 任务已从“只排槽并报未配置”改为执行账号发现和内容更新；供应商余额、鉴权或预算阻断时按供应商熔断，后续记录明确标记跳过。
- 原始响应现在可关联账号或内容；新增账号供应商引用表，数据库 schema 版本升为 3，并提供旧库加列迁移。
- 页面启用账号/内容全部操作按钮、CSV 文件选择、表单弹窗、操作结果提示、复核与更新数据并列操作。

## 发现的问题及修复

- 非交互 shell 找不到 `uv`：验证统一改用项目 `.venv` 中的锁定命令，不跳过检查。
- 成功槽原先只按供应商和适配器拦截，存在换供应商重复付费风险：更新入口先按内容、阶段和业务窗口查询任意成功槽，全局阻断重复请求。
- 账号更新原先删除并重建全部平台身份，会连带删除已缓存 `sec_user_id`：改为按平台原位更新；只有 UID 真正变化时才删除对应供应商引用。
- 综合检查误把 `.mjs` 传给 Python Ruff：该命令失败未计为通过，随后按语言边界分别重跑 Ruff、Mypy、ESLint 和 TypeScript，全部通过。
