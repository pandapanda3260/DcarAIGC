# 卖点标准维护与发布约定

卖点页面用于查看正式标准、适用场景和命中统计。运营不在页面新增、编辑、删除或发布规则。需要调整时，用下面的模板描述业务要求，由后端统一处理。

## 运营提交模板

- 调整对象：已有卖点编码和名称；新增需求写“新增”，编码由后端确认。
- 调整原因：当前判断存在什么问题，影响哪些业务。
- 希望识别的内容：用业务语言说明。
- 不应识别的内容：容易混淆或需要排除的情况。
- 正例：内容链接及应命中的原因。
- 反例：内容链接及不应命中的原因。
- 边界情况：与哪些现有卖点可能冲突，预期如何区分。
- 数据范围：只影响今后内容，还是需要按新口径重算指定日期范围。
- 报告需求：是否需要另出新口径报告，列出日期范围。
- 确认人及期望完成时间。

无需填写 JSON、评分表达式、词集、阈值或规则哈希。业务说明不等于已生效规则。

## 后端处理顺序

1. 区分纯名称/说明调整与识别逻辑、层级、场景、编码、评分或阈值变更，列出具体差异。
2. 对照正式规则来源核查。配置文件、数据库草稿、正式规则快照和离线实验不是自动同步的同一份数据。
3. 用固定正反例比较新旧结果，检查容易混淆的现有卖点。验证单条规则格式，也验证整套规则、公共参数和批准编码集合。
4. 明确历史重算范围和可用证据。优先复用已有证据；补抓、付费调用和范围扩大需在本次变更中单独明确。
5. 准备适用于当前版本的候选数据、校验、整体激活与回退步骤；校验通过后才切换正式版本。保留旧评估结果，不直接覆盖同一版本的正式规则。
6. 核对正式标准、内容标签、卖点统计及线上同步口径。历史冻结报告保留原版；需要新口径时另建更正任务。

## 数据刷新含义

- 页面刷新：重新读取数据，不执行内容识别。
- 平台数据更新：获取曝光、互动等平台指标，不等于规则重算。
- 规则重算：在明确范围内按指定规则版本产生评估结果，不等于发布正式版本。
- 正式切换：标准与评估版本、统计读取口径一起变更，不允许先换标准再无范围地补算。
- 报告更新：旧任务复用其冻结输入；跨规则版本出数需要新的更正任务。
- 线上同步：有独立的版本和快照校验，不等于前端代码更新。
