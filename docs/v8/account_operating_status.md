# 账号状态

账号页使用“账号状态”列和筛选，支持日更、周更、暂停。日更和周更是人工填写的作品更新频率，不改变任何采集周期、预算或供应商规则。没有人工选择的既有账号显示“待标记”，不根据历史发帖推断频率。

暂停以同一事务保存账号启停事件、下一版系统名单和人工操作回执：立即停用采集、从有效名单查询和新统计中排除。当前已封存的名单证据、历史内容和已经冻结的报告保持原样。恢复时选择日更或周更；名单快照继续遵守现有北京时间零点激活边界，重复恢复不重复生成同一名单。

人工标记复用持久控制回执机制，兼容已经安装的 schema20，不再增加数据库列或执行迁移。固定 `operator_account_status` 类型不注册为定时任务，不进入采集任务列表。父记录与唯一成功 attempt 绑定相同规范 JSON、账号身份、请求编号和校验哈希；终态 attempt 不可更改或删除，随现有 SQLite 备份保留。重复的同一请求返回原结果，不能把随后修改的频率覆盖回去；请求编号对应不同意图会被拒绝。记录损坏时明确报错，不悄悄回退旧标签。

频率读模型按账号批量读取已验证回执，不新增 accounts 字段。账号运营字段、频率、enabled、名单及回执任一步失败时全部回滚。统计统一复用 paused 账号排除条件；已冻结报告保留其原始输入，新报告首次冻结时才按当前账号状态选取。

账号目录不再提供“当前成员 / 历史档案 / 待身份对齐”三套入口，账号列表及导出统一使用账号状态筛选；暂停账号仍能查阅。内部名单快照继续承担定时生效、路由和采集授权的实际作用，不把这些内部证据作为另一套账号状态。

“等待匹配”面板、接口字段和运行时汇总写入均已停用。导入、内容更新和采集仍按平台与 UID 关联真实账号，不再维护单独的待匹配队列。旧 `pending_platform_identities` 表及历史迁移兼容代码保留，不在这次同库代码更新中删表或重写历史数据。

新增系统账号填写抖音或小红书主页链接、账号状态，手机号和运营人员可以留空。后端解析真实平台 UID 并补齐公开资料，按平台与 UID 判重，不能用手机号或昵称合并账号；小红书 UID 忽略大小写。重复提交已生效账号会明确拒绝，恢复暂停账号使用原账号 ID 和历史记录。旧 UID 表单、独立启停及移出名单入口不能绕过新的状态流程。

新增或恢复日更、周更账号时，身份、运营信息、人工回执、名单与采集衔接在同一事务内保存；无法建立有效采集安排则全部回滚。新名单仍按北京时间次日零点生效，页面返回实际生效时间；暂停立即停止后续采集，不等待零点。重试同一请求编号不重复新增或覆盖后来的修改。公开资料暂时无法读取时明确返回失败，不保存无法确认的账号。

账号页面、RSC 数据及账号管理接口仅管理员和超级管理员可访问。运营人员和新用户既没有导航入口，也不能直接请求这些接口；现有内容查询和内容导出权限不变。

发布沿用已安装 schema20 的同库代码更新，数据库 inode、原迁移和安装记录、采集 RELEASE 与预算/传输授权保持原有校验。在已验证的采集续租修复版本上，只接受审核过的精确文件变更；继承已有的八项采集授权，名单后续变化必须验证完整衔接证据。代码发布不代表用户明确推迟的真实业务 E2E 或传输资格验收已经完成。
