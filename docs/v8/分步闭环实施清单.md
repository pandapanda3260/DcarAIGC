# DCar Insight v8 分步闭环实施清单

本文件冻结 v8 实施边界。每一步只在前一步相关检查全部通过后开始；不得删除测试、降低断言或用静态假数据伪造运行结果。

## 固定架构边界

- v8 使用 `app/data/dcar_insight.sqlite3`；旧 `app/data/web_mvp.sqlite3` 仅供 v7 历史只读。
- v8 报告合同为 `dcar-content-operations-report-v8.0`，不得放宽 v7 validator 来容纳 v8 字段。
- 自动抓取首版只覆盖抖音和小红书；视频号、快手只开放账号管理和人工导入。
- 概览直接查询时间窗口，不建立 v8 正式基线，也不调用 `promote_formal_baseline`。
- 新报告任务只读取已落库数据，不隐式触发付费抓取。
- 指标状态不使用 `partial`；`partial` 只属于任务状态。
- 媒体、ASR、OCR、人工复核均属于正式评估链路，不列为可选增强。

## 正式覆盖率合同值

- 媒体终态覆盖率门槛固定为 `95%`；内容达到 V2/V3，或已明确路由到 `manual_required`、`resolved`、`terminal_failed`，才计入终态覆盖。
- 周报评论证据覆盖率门槛固定为 `90%`，按周报截止时点前最近有效采集窗口计算。
- 早期方案中的“媒体终态 `98%`”与“周报评论 `80%`”已被上述正式合同值取代，不再作为实施或验收依据。
- 本次仅同步方案文档；现行合同与代码已按 `95% / 90%` 执行，不做代码调整。

## 分步顺序和退出条件

1. **冻结基线**：提交机器可读基线及验证测试；现有 162 个 Python 测试和 3 个 Web 测试通过。
2. **v8 数据库与迁移**：新库建表、776 条数据幂等迁移、迁移数字和槽位数字全部精确匹配基线。
3. **v8 报告合同**：新增 v8 validator；v7 五个历史 revision 仍通过冻结合同。
4. **运行环境与 API 骨架**：受管 Python、锁文件、FastAPI、兼容只读 API 可启动；旧 UI 仍可读取。
5. **新页面骨架**：概览、任务、账号、内容、卖点五个导航和只读状态通过构建及渲染测试。
6. **抓取与媒体**：唯一槽位、原始响应、媒体下载、抖音/小红书 ASR+OCR、模型 pin 和 165 条历史媒体终态路由通过。
7. **评估与复核**：增量评估、卖点版本、复核队列、人工证据和新评估版本闭环通过。
8. **任务、报告与调度**：日报、周报、自定义报告、停机补跑、per-run 文件下载通过。
9. **完整交互**：账号/内容 CRUD、导入导出、单条更新和新前端切换通过真实页面验收。
10. **清理与总回归**：清理旧壳和硬编码路径，完成构建、Lint、类型检查、全量测试及真实 E2E。

## 测试纪律

- Python 基线命令：`PYTHONPATH=src/dcar_eval python3 -m unittest discover -s tests -p 'test_*.py'`。
- Web 渲染基线命令：在 `app/web` 运行 `npm test`。
- 每一步先运行新增或受影响的定向测试，再运行该层完整测试。
- 发现失败必须在当前步骤修复并重新执行相同命令。
- 供应商请求只能在预算表、唯一槽位和原始响应登记全部可用后执行。

## 付费补证硬边界

- 165 条 V1 待复核视频中，1 条已有本地视频、ASR 和 OCR，只做零成本重评估。
- 164 条历史 Rnote 媒体来源刷新槽及其 20 条试采记录只为审计保留，不再允许通过 Rnote 重试；失败、预算和 HTTP 402 事实不得改写或删除。
- 后续付费媒体来源刷新只允许走 TikHub 当前生产适配器，沿用唯一 lifetime 槽、显式授权预算和原始响应 SHA-256 登记；预算登记缺失或唯一槽位不可用时必须阻断请求。
- 任何旧 Rnote collector、adapter 或 CLI 在读取凭据、消耗预算或发请求前必须以 `Rnote retired; use TikHub` 失败关闭；缓存解析、迁移和历史报告读取不受影响。
- 阶段完成定义是 165 条全部到达 `evidence_ready`、`manual_required` 或 `terminal_failed`，不是全部达到 V2。
