# 懂车帝内容评估判断标准与流程 v5.0（终版）

日期：2026-08-02  
适用渠道：抖音、小红书；渠道必须隔离统计。  
正式卖点体系：`business_selling_points_v4_final.json`。  
机器输出合同：`report_contract_v7.json`。

> **口径修订（2026-08-17）**：本标准原有的"人工复核"环节已整体取消——判定全程自动，无复核队列、无人工改判入口（schema v16 已删除复核域）。下文第十二、十四节相关表述按此修订，60—74 分弱匹配仍不计入覆盖率，只是不再有"复核后计入"的路径。
主口径：唯一平台内容ID对应的一条发布；相同创意由不同账号或不同内容ID发布仍分别计数。

## 一、最终输出对象

系统对每条发布输出四组判断，并在渠道与业务场景层汇总：

1. 内容表达的懂车帝主卖点及最多两个次卖点；
2. 内容汽车性；
3. 互动受众汽车性；
4. 懂车帝拉新潜力。

渠道和业务场景同时输出卖点条数分布、卖点曝光分布、数据覆盖、失败和弱匹配诊断。逐条判断不是Web和报告的全部输出。

## 二、废除实际拉新字段

从v5起，实际拉新效果不属于本系统的判断对象、数据字段、明细字段、渠道指标或报告内容。新代码和v7输出不得包含`actual_acquisition_score`、`actual_acquisition_status`、`actual_acquisition_effect`或同义字段，也不再输出“尚未测试”“等待懂车帝侧归因”等占位文案。

历史v4规则和v6.2报告保持冻结，仅作为历史基线。新系统只输出实验前预测指标“懂车帝拉新潜力”，键名固定为`acquisition_potential`。

## 三、业务场景和卖点体系

业务场景固定为：二手车、新车、媒体-AI小懂。核心卖点固定为`E1、E2、X1、X2、X3、M1、M2、M3`；其余正式标签为其他卖点。卖点必须表达用户通过懂车帝能够完成的任务或获得的平台能力，普通汽车知识、娱乐性和账号归属本身不构成懂车帝卖点。

每条内容只允许一个主卖点参与汇总，最多两个次卖点。具体交易、选买、AI任务优先于泛内容服务标签。

## 四、完整内容证据

证据按以下顺序读取：视频ASR、视频字幕和关键帧OCR、关键帧语义、图文全部原图、正文、封面和话题、评论。评论只用于内容主题校准和互动受众判断，不能替代内容主体。

| 等级 | 条件 | 是否进入正式卖点判断 |
|---|---|---|
| V3 | 有效ASR并有OCR、关键帧或原图共同覆盖主叙事 | 是 |
| V2 | ASR、连续字幕OCR、关键帧或全部原图至少一项完整覆盖主叙事 | 是 |
| V1 | 只有标题、正文、封面或话题 | 否，进入补采 |
| V0 | 内容主体和有效文字均不可用 | 否 |

## 五、卖点评分

正式命中必须同时满足：用户任务明确、懂车帝能力能够承接、媒体主体存在证据、属于主叙事或关键解决方案、证据为V2/V3、总分不低于75分。

| 维度 | 分值 |
|---|---:|
| 标签语义匹配 | 30 |
| 懂车帝承接关系 | 25 |
| 完整媒体证据 | 20 |
| 用户收益明确度 | 15 |
| 主叙事突出度 | 10 |

90—100为强匹配，75—89为明确匹配，60—74为弱匹配，0—59为未命中。60—74分不计入卖点覆盖率。

## 六、条数维度

每个渠道和场景固定输出：可识别内容、卖点覆盖、核心卖点覆盖、其他卖点覆盖。`核心 + 其他 = 卖点覆盖`；可识别内容与卖点覆盖重叠，不能画成互斥分桶。

补充诊断固定放在`count_distribution.diagnostics`：未命中卖点、不可识别、V2/V3、V0/V1、证据覆盖率、失败、弱匹配。

渠道核心卖点生产目标使用：`渠道核心主卖点发布数 / 渠道全部发布数`，目标区间60%—70%。目标差距只在渠道级展示。

场景主表中的条数指标表示场景对全渠道的贡献，分母仍为渠道全部发布。场景另行输出“场景内部核心发布占比”，公式为`场景核心主卖点发布数 / 场景全部发布数`，但不得与渠道60%—70%目标比较。

## 七、曝光维度

只接受平台真实播放量或浏览量。固定输出可识别内容曝光、卖点覆盖曝光、核心卖点曝光、其他卖点曝光。分母统一为渠道有效总曝光；场景指标表示场景对渠道有效总曝光的贡献。

标签与有效曝光的交叉覆盖达到90%才可输出渠道曝光结论。低于90%时四项曝光指标均为`unavailable`，不能用样本值或0%冒充业务结果。有效总曝光、有效内容数、缺失数、异常0值数、交叉覆盖数和不可计算原因固定放在`exposure_distribution.coverage`。

## 八、内容汽车性

内容汽车性由正文、完整图片、视频、ASR和OCR共同判断。评论最多作正负5分校准；没有评论不阻止内容汽车性输出。0—39不属于汽车内容，40—69与汽车有关但不是明确主体，70—84主体属于汽车内容，85—100明确属于汽车内容。

## 九、互动受众汽车性

互动受众汽车性按有效独立评论用户计算。有效用户必须具有稳定平台用户标识和有效语义；作者回复、广告、垃圾互动、纯表情和无稳定身份的评论不计入。

有效独立评论用户少于20时，逐条互动受众分数必须为`null`，显示“— / 暂不可计算”。已确认0评论、有效用户不足和技术采集失败必须分别记录。

匿名用户键固定为：`HMAC-SHA256(local_stable_salt, platform + content_id + raw_platform_user_id)`。只允许在同一内容内去重，不建立跨内容用户画像。原始ID、昵称、头像、主页和位置不落盘；本地盐权限为0600且不提交Git。

## 十、懂车帝拉新潜力

权重固定为：内容汽车性20%、互动受众汽车性25%、懂车帝任务承接35%、行动意图20%。

任一组成项缺失时，拉新潜力必须为`null`并显示“— / 暂不可计算”。禁止补0、禁止默认分、不重加权，也禁止对其余维度重新归一。互动受众少于20名有效独立用户时，拉新潜力必然不可计算。

渠道和场景只聚合可计算内容：全量可计算为`available`，部分可计算为`sample_only`，0条可计算为`unavailable`。`sample_only`不得上卷为全部发布结论。

## 十一、任务和采集边界

相同平台、内容ID、数据类型和请求参数版本存在终态缓存时不得再次请求。终态包括成功、已确认为空、内容删除、永久不可访问和接口明确不支持。

请求首次失败后，仅超时、DNS临时失败、连接重置或中断、TLS握手中断、HTTP 408、429、5xx和传输残缺JSON允许自动重试一次；每个请求总尝试不超过两次。其他4xx、参数错误、认证错误和业务语义错误不自动重试。

## 十二、正式基线

首页只读取正式基线。正式基线必须是当前规则版本下通过合同校验、报告非陈旧的完整双渠道全库任务；临时、样本和单渠道任务不能替换正式基线。

证据或规则变化触发重新评估后，必须将报告标为陈旧，重新计算该 run 的汇总与全部导出，报告修订号加一并保留上一版本。重算不得重新调用采集接口。

## 十三、固定报告顺序

1. 抖音汇总；
2. 抖音三个业务场景；
3. 小红书汇总；
4. 小红书三个业务场景；
5. 结论摘要；
6. 抖音内容明细；
7. 小红书内容明细；
8. 配套文件。

所有比例必须展示分子、分母、百分比、定性、范围和原因。评分必须展示分数、满分、可计算内容数、总内容数、覆盖率、定性、范围和原因。数据覆盖0%不能写成业务结果0分或0%。

## 十四、质量控制

每次全量任务必须在质量看板上核对核心卖点、60—74 分弱匹配、V0/V1、情感剧情和片尾植入内容的规模与分布，异常由规则修订解决（本系统无人工逐条改判）。规则变化必须提升版本并全量重跑；同一报告禁止混用规则版本。
