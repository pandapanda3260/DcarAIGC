# 懂车帝内容评估判断标准与流程 v4.2（终版结构）

日期：2026-08-02  
适用渠道：抖音、小红书；两个渠道必须分开统计，只接受对应平台的内容链接。  
主口径：全部发布口径。一个唯一平台内容ID/链接计一条发布；相同内容被不同账号或不同内容ID再次发布，仍分别计入。不再以去重创意口径作为主结论。

## 一、最终要回答的四个问题

1. 内容表达了懂车帝的哪个业务卖点；
2. 内容本身是否属于汽车内容；
3. 互动用户是否偏汽车；
4. 内容是否带来懂车帝实际拉新。

卖点分布与内容垂直度是两套不同指标：汽车内容不一定表达懂车帝卖点；表达卖点也必须有完整内容证据，不能只看标题、标签或账号归属。

## 二、三个业务场景

最终只保留三个业务场景：

1. 二手车；
2. 新车；
3. 媒体-AI小懂。

原“媒体内容与社区”不再作为第四业务线。C1-C4保留为正式卖点标签，但每条内容须按实际用户任务动态归入上述三个场景之一。

| 标签 | 二手车 | 新车 | 媒体-AI小懂 |
|---|---|---|---|
| C1 实用汽车知识和用车解答 | 二手车鉴别、二手交易、二手车整备或用车任务 | 若已形成明确新车决策任务，优先改标X类 | 泛驾驶、安全、零件、保养、维修、应急知识 |
| C2 车型细节、真实影像和体验 | 二手车源、车况、实车体验 | 新车或在售车型的外观、内饰、空间和使用体验 | 不作为默认归属 |
| C3 车友社区 | 不作为默认归属 | 不作为默认归属 | 车友交流、改装、玩车和社区创作 |
| C4 发布与行业动态 | 二手车市场、交易和行业动态 | 新车发布、上市、销量和汽车行业动态 | 仅确属媒体/社区服务且不能归入前两者时使用 |

业务场景是汇总维度，不改变C1-C4均为“其他卖点”的层级。

### 1. 二手车

### 4. 跨场景延展卖点（逐条归入前三个场景，不单列业务）

下列标签继承原“媒体内容与社区”的能力表达，但不再形成第四业务线。打标时必须根据具体用户任务，将每条发布归入二手车、新车或媒体-AI小懂中的一个场景。

| ID | 层级 | 卖点 |
|---|---|---|
| C1 | 其他 | 通过懂车帝获取实用汽车知识和用车问题解答 |
| C2 | 其他 | 通过懂车帝查看车型细节、真实影像和场景化体验 |
| C3 | 其他 | 通过懂车帝车友社区交流用车体验并参与玩车内容 |
| C4 | 其他 | 通过懂车帝跟踪新车发布和汽车行业动态 |

核心卖点集合固定为：`E1、E2、X1、X2、X3、M1、M2、M3`。核心卖点60%-70%的目标按“主卖点为核心的发布条数 / 全部发布条数”计算，次卖点不能抬高比例。

## 四、完整内容证据标准

终版不再输出“仅标题/正文判断”的业务结论。

证据读取顺序：

1. 视频口播/对白ASR；
2. 视频字幕和关键画面OCR；
3. 关键帧画面语义；
4. 图文笔记全部原图及图片文字；
5. 作品正文；
6. 封面文字、话题标签和账号属性，仅作辅助；
7. 评论用于内容主题验证和受众判断，不替代作品主体证据。

| 等级 | 条件 | 是否进入终版 |
|---|---|---|
| V3 完整 | 有效ASR，并有OCR/关键帧/原图语义共同覆盖主叙事 | 是 |
| V2 可用 | ASR、连续字幕OCR、关键帧或整组原图至少一项完整覆盖主叙事 | 是 |
| V1 不完整 | 只有标题、正文、封面或话题，没有读取实际视频/图片主体 | 否，只进入补采队列 |
| V0 缺失 | 内容主体与有效文字均不可用 | 否 |

## 五、卖点判定规则

### 1. 必要条件

一条内容正式命中卖点，必须同时满足：

1. 能识别具体用户任务；
2. 任务可以由懂车帝产品、交易、AI、媒体或社区能力承接；
3. 实际视频/图片主体中有证据；
4. 卖点是主要叙事或关键解决方案，不是片尾口播、Logo、话题或孤立一句话；
5. 主卖点评分至少75分，证据等级为V2或V3。

### 2. 100分评分

| 维度 | 分值 |
|---|---:|
| 标签语义匹配 | 30 |
| 懂车帝承接关系 | 25 |
| 完整媒体证据 | 20 |
| 用户收益明确度 | 15 |
| 主叙事突出度 | 10 |

| 分数 | 定性 | 处理 |
|---|---|---|
| 90-100 | 强匹配 | 计入正式卖点 |
| 75-89 | 明确匹配 | 计入正式卖点 |
| 60-74 | 弱匹配待复核 | 不计入覆盖率 |
| 0-59 | 未命中 | 不计入覆盖率 |

### 3. 主叙事占比规则

情感、人生故事、末日、娱乐、概念视觉等内容必须先判断主叙事：

- 懂车帝任务仅出现在中后段短暂植入、片尾口播、UI截图或品牌露出时，不命中卖点；
- 汽车或懂车帝只是推进剧情的道具时，不命中卖点；
- 只有当用户任务贯穿内容，或构成解决核心冲突的关键路径，才进入卖点评分；
- 不能因为账号是懂车帝自有/合作账号而自动命中。

本规则优先级高于关键词匹配。

### 4. 多标签

- 每条内容只允许1个主卖点参与汇总；
- 最多2个次卖点，必须有独立证据；
- 具体产品、交易或AI任务优先于C1-C4内容服务；
- 具体新车/二手车决策任务优先于泛知识或车型展示。

## 六、卖点分布指标

### 1. 条数维度

全部指标均以渠道内全部唯一发布链接为基础：

- 可识别内容 = V2/V3发布条数；
- 卖点覆盖 = 主卖点>=75且V2/V3的发布条数；
- 核心卖点覆盖 = 主卖点属于核心集合的发布条数；
- 其他卖点覆盖 = 主卖点属于其他集合的发布条数；
- 未覆盖/不可识别 = 全部发布 - 卖点覆盖。

注意：可识别内容是证据完整度指标；核心和其他是卖点覆盖的内部拆分。`核心 + 其他 = 卖点覆盖`，但可识别内容与卖点覆盖会重叠，不能画成四个互斥分桶。

### 2. 曝光维度

只接受平台真实播放量/浏览量：

- 可识别内容曝光 = 可识别发布的曝光之和 / 全部有效曝光；
- 卖点覆盖曝光 = 正式卖点发布的曝光之和 / 全部有效曝光；
- 核心卖点曝光 = 核心主卖点发布的曝光之和 / 全部有效曝光；
- 其他卖点曝光 = 其他主卖点发布的曝光之和 / 全部有效曝光。

质量门槛：

1. 曝光必须与内容ID同一快照匹配；
2. 占位值、异常0值和缺失值不视为真实曝光；
3. 必须同时具备卖点标签和有效曝光的内容覆盖率达到90%，否则渠道曝光分布输出“不可计算”；
4. 点赞、评论、收藏、分享不能替代曝光。

## 七、内容垂直度三个命题

### 命题1：内容汽车性

判断对象是内容主叙事，而不是账号、链接来源或汽车标签。

基础分由正文/标题主题与实际图片/视频主体综合得到；评论主题最多作正负5分校准。评论缺失不阻止内容判断，但必须标明未使用评论验证。

| 分数 | 定性 |
|---|---|
| 85-100 | 明确属于汽车内容 |
| 70-84 | 主体属于汽车内容 |
| 40-69 | 与汽车有关，但汽车不是明确主体 |
| 0-39 | 不属于汽车内容 |

渠道输出同时提供：平均内容汽车性分数、达到70分的发布条数及其占全部发布比例。

### 命题2：互动受众汽车性

按有效独立评论用户评分：

| 用户分 | 证据 |
|---|---|
| 100 | 明确车主身份、正在买卖车、维修用车或有具体车型决策需求 |
| 70 | 展现具体车型、配置、价格、用车或汽车知识理解 |
| 30 | 泛汽车反应、复述内容、仅表示喜欢某车 |
| 0 | 非汽车、泛娱乐、广告、无语义或垃圾互动 |

笔记/视频得分为有效独立评论用户均分。有效用户少于20时不输出结果；抽检流程中应跳过并按预先冻结的同层随机队列补抽，直到每个目标样本达到20人或候选池耗尽。

频道汇总必须说明样本设计。为满足评论门槛而替补得到的高评论内容，只能代表“评论可评估内容”，不能直接上卷为全部发布受众。

### 命题3：内容拉新效果预估

拉新效果预估是用于决定哪些内容值得进入拉新实验的0-100分，不是实际新增结果。统一模型使用：内容汽车性20%、互动受众汽车性25%、懂车帝任务承接35%、评论/内容行动意图20%。四项证据不齐时不强行补0；缺少互动用户或行动意图时输出“暂不可计算”。

| 分数 | 定性 |
|---|---|
| 80-100 | 具备明确下载理由，建议优先进入拉新实验 |
| 65-79 | 存在清晰承接需求，值得进入拉新实验 |
| 40-64 | 与懂车帝有关联，但下载理由不足，只建议小流量验证 |
| 0-39 | 缺少迁移到懂车帝的理由，当前不建议用于拉新 |

### 实际拉新效果（后验验证，不与预估混写）

实际效果只能来自懂车帝侧实验归因，至少需要：

- 渠道内容ID；
- 曝光；
- 懂车帝落地页点击；
- 下载/激活；
- 登录；
- 确认新增用户；
- 对照组或可识别的自然新增基线；
- 归因窗口和去重规则。

没有这些数据时实际效果统一输出“尚未测试/不可计算”，不得用拉新潜力、评论意向、品牌露出或下载理由替代实际效果。

## 八、渠道隔离与抽样

- 抖音结论只能使用抖音内容链接和抖音评论/曝光；
- 小红书结论只能使用小红书内容链接和小红书评论/曝光；
- 不允许用一个渠道的卖点或受众结论外推另一个渠道；
- 样本结果必须明确写“样本”，不得冒充全发布结果；
- 全发布结论要求逐条完整媒体证据覆盖全部内容，或报告未覆盖条数并停止上卷。

## 九、质量控制

每次全量重跑必须：

1. 人工复核全部核心卖点；
2. 人工复核全部60-74分；
3. 人工复核情感、剧情、末日、概念视觉和片尾植入内容；
4. 按账号类型分别抽检至少10%的正式命中与未命中；
5. 检查ASR数字、OCR误识别、车型/价格语境、标题与内容不一致；
6. 规则调整后提升版本号并全量重跑；
7. 同一报告中禁止混用不同规则版本。

## 十、终版输出结构

抖音和小红书必须分别输出，两个渠道均固定为以下三层：

1. 汇总：卖点条数占比、核心卖点条数占比、卖点曝光占比、核心卖点曝光占比、内容垂直度、互动用户垂直度、内容拉新效果预估；
2. 三个业务场景：二手车、新车、媒体-AI小懂逐场景重复上述七项指标。
3. 内容明细：逐条展示每条发布的链接、业务场景、卖点、核心卖点、曝光、内容垂直度、互动用户垂直度和内容拉新效果预估。

条数占比分母统一为该渠道全部发布；场景占比表示该场景对全渠道的贡献。曝光占比分母统一为该渠道有效总曝光。场景内容/用户/拉新得分必须写明实际进入计算的场景样本范围。

数据缺口和适用范围放在对应指标旁，不再单独打乱主结构。样本结果必须显示“样本”，不可计算必须显示“—/暂不可计算”，不得用0%替代缺失结论。

所有数据项统一采用“数字 + 百分比 + 定性描述”：例如`78/100，385/438=87.90%，主体属于汽车内容`。数据缺失时，数字与百分比只表达数据覆盖率，例如`0/438条可评估，0%数据覆盖，暂不可计算`，不得将覆盖率0%写成业务结果0%。

逐条明细继续保留：平台、内容ID、链接、证据等级、主/次卖点、业务场景、核心/其他、分值、定性、证据、内容垂直度、互动用户垂直度、拉新效果预估及实际拉新状态。
